# События и восстановление

VoiceRoute доставляет сообщения через отдельный SSE-поток канала. SSE ID является
курсором изменений и не совпадает с `message.seq`. Начальная выдача может не иметь
SSE ID, поэтому библиотека хранит оба значения в `StreamCheckpoint`:

- `message_seq` — последнее успешно обработанное сообщение;
- `change_cursor` — последний успешно обработанный SSE change cursor.

## Гарантия обработки

Checkpoint записывается после завершения пользовательского обработчика. Если
обработчик или процесс завершится с ошибкой раньше, позиция не продвинется и
событие будет получено повторно. Это модель at-least-once: обработчики внешних
побочных эффектов должны быть идемпотентными.

`Context.reply()` формирует стабильный UUID из исходного сообщения, команды и
номера ответа. Поэтому повторное выполнение того же ответа не создаёт новое
сообщение.

## Постоянное хранение

```python
from voiceroute import Bot, FileCursorStore

bot = Bot(
    token="...",
    cursor_store=FileCursorStore(".voiceroute/cursors.json"),
)
```

Файл заменяется атомарно и создаётся с правами `0600`. Адаптер рассчитан на один
процесс. Несколько процессов не должны одновременно записывать один файл; для
горизонтального запуска потребуется общий SQLite/Redis-адаптер с координацией.

Без явно переданного хранилища используется `MemoryCursorStore`. Он удобен для
тестов, но теряет checkpoint при завершении процесса.

## Разделение потоков

Ключ включает origin, тип потока, community ID и channel ID. Cursor нельзя
переносить между production/dev, каналами или разными типами событий.
