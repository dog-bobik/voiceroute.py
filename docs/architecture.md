# Архитектура

Библиотека строится слоями и не связывает пользовательский API с деталями сети.

```text
Bot framework
    -> Resource APIs
        -> HTTP and SSE transports
            -> VoiceRoute API
```

## Transport

Transport отвечает за авторизацию, URL, JSON, таймауты, rate limits, retries и
преобразование HTTP-ошибок. Он не содержит бизнес-объектов и команд.

Один `VoiceRouteClient` разделяет sliding-window limiter между resource API и
открытием SSE. Retry разрешён по умолчанию только безопасным HTTP-методам.
Изменяющая операция обязана явно подтвердить идемпотентность; отправка сообщения
делает это благодаря стабильному `clientMessageId`.

## Resource API

Модули `api` группируют endpoint-ы по предметной области. Сырые ответы
преобразуются в типизированные DTO из `models`.

## Events

Runtime получает события через протокол `EventTransport` и не зависит от сетевого
формата. Текущий `LegacySSETransport` объединяет постраничное восстановление истории и
канальный SSE в поток `EventDelivery`. Каждая доставка содержит нормализованное событие,
источник и checkpoint, который runtime сохраняет только после успешной обработки.

Пользовательский transport можно передать через `Bot(..., event_transport=...)`. Это
позволяет тестировать runtime без сети и позже добавить Gateway-адаптер без изменения
команд и обработчиков бота.

SSE-потоки используют отдельные курсоры. События сообщений применяются как
upsert, пока серверный контракт не позволяет достоверно различить создание и
изменение без локального состояния.

Runtime сохраняет составной checkpoint: `message_seq` закрывает начальную выдачу,
у которой ещё нет SSE ID, а `change_cursor` восстанавливает поток изменений.
Checkpoint фиксируется только после успешной обработки события. Хранилище
задаётся через протокол `CursorStore`; встроены process-local и атомарный файловый
адаптеры. Файловый адаптер предназначен для одного процесса.

## Commands

Команды являются клиентской абстракцией поверх обычных сообщений. Библиотека не
имитирует отсутствующие на сервере interactions, intents или gateway.

`CommandRegistry` хранит метаданные, aliases и многоуровневые пути, а `Command` отвечает
за типизированное преобразование аргументов и вызов callback. `PrefixCommandAdapter`
только преобразует текст сообщения в независимый `CommandInvocation`. Будущий adapter
interactions сможет использовать тот же registry и pipeline.

`CommandPipeline` последовательно выполняет checks, cooldown, concurrency gate и
middleware. Состояние встроенных ограничителей локально процессу; распределённые
адаптеры хранения будут добавлены отдельно и не должны менять публичные декораторы.

## Границы безопасности

Runtime-клиент принимает только bot token. Управление приложениями через cookie,
пароль и MFA не входит в него и при необходимости будет реализовано отдельно.
