# voiceroute.py

Асинхронный Python SDK и фреймворк для разработки ботов в
[VoiceRoute](https://voiceroute.cc).

> [!WARNING]
> Проект находится на ранней стадии разработки. Публичный API может меняться до
> выпуска версии `1.0.0`.

## Цели проекта

- типизированный асинхронный клиент HTTP API;
- надёжная обработка SSE с восстановлением курсора;
- идемпотентная отправка сообщений;
- удобная событийная модель и команды в стиле современных bot-фреймворков;
- расширяемая архитектура без смешивания bot token и пользовательской сессии;
- безопасная работа с лимитами запросов, повторными попытками и секретами.

## Установка для разработки

Требуется Python 3.11 или новее.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
```

Примеры автоматически читают локальный `.env` из корня репозитория. В нём
достаточно указать `VOICEROUTE_BOT_TOKEN`; production используется по умолчанию.

Полноценный демонстрационный пример: [Community Assistant Bot](examples/community_assistant/README.md).

## Минимальный бот

```python
import os

from voiceroute import Bot, Context, FileCursorStore

bot = Bot(
    token=os.environ["VOICEROUTE_BOT_TOKEN"],
    cursor_store=FileCursorStore(".voiceroute/cursors.json"),
)


@bot.command()
async def ping(context: Context) -> None:
    await context.reply("Pong!")


bot.run()
```

Ответ использует стабильный UUID, производный от исходного сообщения. Повторная
доставка SSE-события поэтому не создаст дубликат ответа.

По умолчанию команды принимают оба привычных префикса: `/ping` и `!ping`.
Собственный префикс задаётся через `Bot(..., command_prefix="?")`.

Команды поддерживают aliases, группы и типизированные позиционные аргументы. Метаданные и
вызов не зависят от prefix transport, поэтому будущие server-native interactions можно
будет подключить отдельным адаптером. Подробнее: [командный фреймворк](docs/commands.md).

Команды и listeners больших ботов можно объединять в расширения с атомарной загрузкой,
выгрузкой и reload. Подробнее: [расширения](docs/extensions.md).

Runtime поддерживает явные состояния, graceful shutdown и изоляцию channel consumers с
ограниченным backoff. Подробнее: [жизненный цикл runtime](docs/runtime.md).

Клиент умеет редактировать и удалять сообщения, управлять закреплением и реакцией,
читать pins и выполнять поиск. Подробнее: [контентный API](docs/content-api.md).

По умолчанию бот обнаруживает все доступные ему сообщества и текстовые каналы.
Для ограничения одним каналом можно явно передать `community_id` и `channel_id`.
При первом подключении он запрашивает историю после `seq=0`, чтобы не пропустить
команды, отправленные незадолго до запуска. Идемпотентные ответы защищают от
дубликатов при повторном получении тех же сообщений.

`FileCursorStore` атомарно сохраняет обработанную позицию с правами `0600`.
Cursor обновляется только после успешного завершения обработчика, поэтому после
сбоя событие будет доставлено повторно. Для нескольких процессов доступны SQLite и
Redis. Подробнее: [события и восстановление](docs/events.md).

Все HTTP-операции одного клиента используют общий лимитер 50 запросов в секунду.
Безопасные запросы и идемпотентная отправка сообщений повторяются после временных
сетевых ошибок; `429` соблюдает `Retry-After`. Подробнее: [сеть и повторы](docs/network.md).

## Безопасность

Не добавляйте bot token в исходный код, URL, query-параметры или логи. Используйте
переменные окружения и передавайте токен только через официальный заголовок
авторизации. Инструкции по сообщению об уязвимостях находятся в
[SECURITY.md](SECURITY.md).
